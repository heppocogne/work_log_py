# 行動ログツール 実装計画（Python版）

## 1. 目的

自分の作業時間の使い方を後から見直せるようにする。
「何を開いていたか（生データ）」を自動で記録し、「何をしていたか（タスク）」を人が付ける。

## 2. 基本方針

- **生データと意味付けを分ける**
  - 生データ（ウィンドウ切替・離席など）は自動収集し、書き換えない
  - タスクの割り当ては何度でも付け直せる
- **どれか1つの仕組みに依存しない**
  - メモファイルや特定アプリに依存せず、複数の弱い信号を重ねる
- **忘れても壊れない**
  - 登録を忘れても、生データから後で復元できるようにする
- **小さく作って実データで判断する**
  - Phase 1 は「収集＋手動登録」のみ。数日使ってから次に足す機能を決める
- **低レベルな Windows API は無理に使わない**
  - メッセージループやフックが必要な機能は、ポーリングや代替手段で妥協する

## 3. 想定する作業環境

- 主に使うアプリ：PowerPoint（手順書・参考資料）、VS Code（メモ）、リモートデスクトップ（接続先固定）
- 手順書・メモは作業ごとに別ファイル。参考資料を同時に開いていることもある
- 1つの作業の中で、上記3つを頻繁に行き来する
  - → ウィンドウ切替＝タスク切替ではない
- 会社 PC で exe の実行は不可。Python スクリプトは実行できる

## 4. フェーズ構成

| Phase | 内容 | 状態 |
|---|---|---|
| 1 | 収集＋タスク手動登録＋簡易確認画面 | **今回** |
| 2 | 定期確認（まだ○○中？） | 後回し |
| 3 | 見返し画面（時間枠ごとの集計＋範囲割り当て） | 後回し |
| 4 | 手順書の検知・ファイル紐づけ・候補表示 | 後回し |
| 5 | タスクツリー管理画面、週・月の集計 | 後回し |

Phase 2 以降の順番は、Phase 1 の検証結果（12章）で決める。

## 5. 技術スタック

| 項目          | 採用                                          | 備考                           |
| ----------- | ------------------------------------------- | ---------------------------- |
| 言語          | Python 3                                    |                              |
| UI          | tkinter（ttk）                                | 標準ライブラリ                      |
| Windows API | pywin32（win32gui / win32process / win32api） | 使えない場合は ctypes で代替可能な範囲に限定する |
| DB          | sqlite3（WAL モード）                            | 標準ライブラリ                      |
| 設定          | TOML                                        | 標準ライブラリ                      |
| 起動          | `pythonw.exe main.pyw`                      | コンソールを出さない                   |
| 自動起動        | スタートアップフォルダに上記のショートカット                      | 管理者権限不要                      |

- 外部パッケージは **pywin32 のみ**とする（pystray・keyboard 等は使わない）
- 使う API は少数なので、pywin32 が入れられない環境でも ctypes で同じことができるよう、
  Windows API 呼び出しは `winapi.py` に集約しておく

## 6. 構成

### 6.1 スレッド方針

**すべてメインスレッド（tkinter のイベントループ）で動かす。**
収集・無操作検知・生存時刻の記録は `root.after()` で定期実行する。

- tkinter と sqlite3 をスレッドをまたいで使う問題を避けられる
- 1秒間隔のポーリング程度なら UI が固まることはない

### 6.2 ファイル構成

```
activity_log/
├─ main.pyw          起動、二重起動防止、定期処理の登録
├─ settings.py       設定の読み書き
├─ winapi.py         Windows API 呼び出しの集約（pywin32 / ctypes）
├─ collector.py      前面ウィンドウの収集
├─ idle_monitor.py   無操作・スリープ・ロックの推定
├─ storage.py        SQLite アクセス、スキーマ管理
├─ task_service.py   タスク作成・切替・割り当ての整合性維持
├─ title_parser.py   タイトルからファイル名等を切り出す（表示用）
└─ ui/
   ├─ overlay.py     常時表示（1行）
   ├─ picker.py      タスク切替の小窓
   └─ daily_view.py  簡易確認画面
```

### 6.3 二重起動防止

- 名前付きミューテックス（`win32event.CreateMutex`）で判定
- 使えない場合は `localhost` の固定ポートへの bind で代替

### 6.4 エラー記録

- `pythonw` ではコンソールが出ないため、例外は `logging` でファイルに出力する
- 定期処理の中で例外が起きても、ループ自体は止めない

## 7. データ構造（Phase 1）

時刻はすべて UNIX ミリ秒（UTC）で保存し、表示時にローカル時刻へ変換する。

```sql
PRAGMA journal_mode = WAL;
PRAGMA user_version = 1;

-- タスク（ツリー）
CREATE TABLE tasks (
  id          INTEGER PRIMARY KEY,
  parent_id   INTEGER REFERENCES tasks(id),
  name        TEXT NOT NULL,
  archived    INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL,
  UNIQUE(parent_id, name)
);

-- 生データ（追記のみ）
CREATE TABLE raw_events (
  id          INTEGER PRIMARY KEY,
  started_at  INTEGER NOT NULL,  -- 終了は次の行の started_at
  kind        TEXT NOT NULL,     -- window / idle / lock / stop
  process     TEXT,
  title       TEXT
);
CREATE INDEX idx_raw_started ON raw_events(started_at);

-- タスクの割り当て（編集可）
CREATE TABLE assignments (
  id          INTEGER PRIMARY KEY,
  task_id     INTEGER NOT NULL REFERENCES tasks(id),
  start_at    INTEGER NOT NULL,
  end_at      INTEGER,           -- NULL = 進行中
  source      TEXT NOT NULL      -- switch / manual
);
CREATE INDEX idx_assign_start ON assignments(start_at);

-- アプリの状態（生存時刻など）
CREATE TABLE app_state (
  key         TEXT PRIMARY KEY,
  value       TEXT NOT NULL
);
```

### ルール

- `raw_events` は終了時刻を持たない。切り替わった瞬間に1行追加するだけ
- `assignments` は**時間帯が重ならない**ように保つ
  - 新しい範囲を登録したら、重なる既存の割り当てを切り詰め・分割する
  - 「今のタスク」は `end_at IS NULL` の1行のみ
  - この処理は `task_service.py` の1か所にまとめ、トランザクション内で行う
- ルート直下の同名タスクは SQLite の UNIQUE では防げない（parent_id が NULL のため）
  - → 固定のルートタスクを1つ作り、すべてをその子にする
  - 「未分類」タスクも初期作成しておく
- タスクは削除せずアーカイブする（過去の割り当てを残すため）
- スキーマ変更は `PRAGMA user_version` を見てマイグレーションする
- 接続は1本を使い回す（メインスレッドのみで使用）

## 8. 収集仕様

### 8.1 ウィンドウ

- `root.after()` で1秒おきにポーリング
  - `win32gui.GetForegroundWindow` → `win32gui.GetWindowText`
  - `win32process.GetWindowThreadProcessId` → プロセスを開いて実行ファイル名を取得
- 前回と「プロセス名＋タイトル」が変わったときだけ `kind = 'window'` で記録
- タイトルは生のまま保存する。ファイル名等の切り出しは表示・集計時に行う
  （切り出しルールを後から直しても過去データに適用できるように）
- 前面ウィンドウが取れない（0 が返る）・タイトルが空の場合は記録しない
- 管理者権限で動くアプリなどでプロセス名が取れない場合は `process = NULL` で記録する
- 自分自身（常時表示・小窓）が前面になったときは記録しない

### 8.2 タイトルの切り出しルール（表示用）

| アプリ              | プロセス名                   | 取り出すもの         |
| ---------------- | ----------------------- | -------------- |
| PowerPoint,Excel | POWERPNT.EXE, EXCEL.EXE | ファイル名          |
| VS Code          | Code.exe                | ファイル名、ワークスペース名 |
| リモートデスクトップ       | mstsc.exe               | 接続先            |
| その他              | —                       | タイトルそのまま       |

実際のタイトル形式は Phase 1 の収集データを見て確定する。
ルールは `title_parser.py` に正規表現のリストとして持ち、追加・修正しやすくする。

### 8.3 無操作

- `win32api.GetLastInputInfo`（または ctypes）を数秒おきに確認
  - 無操作時間は `GetTickCount()` との差で求める（32bit の桁あふれに注意し、差は `& 0xFFFFFFFF` で計算）
  - 閾値（初期値 5分）を超えたら、**最後の操作時刻にさかのぼって** `kind = 'idle'` を記録
  - 操作が再開したら、その時点の前面ウィンドウを `window` として記録
- キーボード・マウスの入力内容はフックしない（最後の操作時刻のみ取得）

### 8.4 ロック・スリープ・終了（妥協部分）

OS の通知（セッション切替・電源イベント）はメッセージループが必要なため使わず、以下で推定する。

| 状態 | 推定方法 | 記録 |
|---|---|---|
| 画面ロック | ロック中は入力がないため、無操作検知で `idle` として扱われる | `idle` |
| スリープ | ポーリング間隔が想定より大きく空いた（例：30秒以上）ら、スリープしていたとみなす | 前回ポーリング時刻で `stop`、再開時に `window` |
| シャットダウン・異常終了 | 次回起動時に生存時刻から補正（8.5） | `stop` |
| ツールの正常終了 | 終了処理で記録 | `stop` |

- ロックとただの離席は区別しない（どちらも「PC を使っていない時間」として扱えば十分）

### 8.5 異常終了対策

- 1分おきに `app_state` に生存時刻を書く
- 起動時、最後の `raw_events` が `stop` でなければ、最後の生存時刻で `stop` を補う
- 進行中の割り当て（`end_at IS NULL`）も同じ時刻で閉じる

## 9. UI 仕様（Phase 1）

### 9.1 常時表示（Overlay）

```
● 案件A / 手順書作成   42分
```

- 表示内容
  - タスク名（長い場合は親を「…」で省略し、葉を優先）
  - 経過時間（分単位）
  - 状態の点：通常＝淡い色、未設定＝目立つ色、離席中＝灰色
- ウィンドウ設定（tkinter の `Toplevel` または `Tk`）
  - `overrideredirect(True)`：枠なし、タスクバー・Alt+Tab に出にくくなる
  - `attributes('-topmost', True)`：最前面
  - `attributes('-alpha', 0.7)`：半透明（マウスを乗せると 1.0）
  - ドラッグで移動、位置を設定に保存
- 妥協点
  - **クリックすると前面ウィンドウが常時表示に移る**（フォーカスを奪わない設定はしない）
    - 常時表示を操作するのは切替時だけなので許容する
    - 収集側では自分自身を記録対象から除外する（8.1）
  - 他のアプリが最前面を取ることがあるため、数秒おきに `lift()` と topmost を再設定する
- 操作
  - クリック：タスク切替の小窓を開く
  - 右クリック：メニュー（簡易確認画面、離席にする、折りたたむ、設定、終了）
  - マウスを乗せる：開始時刻、このタスクの今日の合計（ツールチップ風のラベル）
- 折りたたみ：点だけの小さな表示に切り替えられる（タスクトレイの代わり）
- 高 DPI 環境で文字がぼやける場合は、起動時に DPI 対応を宣言する（ctypes で `SetProcessDpiAwareness`）

### 9.2 タスク切替の小窓（TaskPicker）

- 常時表示のクリックで開く（**グローバルホットキーは Phase 1 では見送り**）
  - 開いたら検索欄にフォーカスを当て、すぐ入力できるようにする
  - Esc で閉じる
- 直近使ったタスクを 1〜9 の数字キーで選択
- 検索欄：部分一致でタスクを絞り込み。候補はパス付きで表示（例：`案件A / 手順書作成`）
- `親/子` 形式で入力すると、存在しない階層はその場で作成
- **開始時刻のさかのぼり指定**を見える位置に置く
  - 「今から」「5分前」「15分前」「30分前」のボタン＋時刻の直接入力（`HH:MM`）
  - さかのぼった範囲に既存の割り当てがあれば切り詰める
- 親タスクにも記録できる（葉まで決めなくてよい）
- 「タスクなし（停止）」も選べる
- 閉じたら、直前に使っていたウィンドウへフォーカスを戻す（`SetForegroundWindow`、失敗しても無視）

### 9.3 簡易確認画面（DailyView）

本格的な見返し画面（Phase 3）までのつなぎ。`ttk.Notebook` でタブ分けする。

- 共通：日付の切り替え（前日・翌日・今日）
- タブ1：割り当て一覧（`ttk.Treeview`）
  - 開始・終了・タスク・経過時間
  - 行をダブルクリックで編集ダイアログ（開始・終了・タスクの変更、削除）
- タブ2：タスク別合計（`ttk.Treeview` をツリー表示）
  - 親タスクには子孫の合計も表示
- タブ3：タイトル履歴（`ttk.Treeview`）
  - 時刻・種別・アプリ・切り出したファイル名
  - 複数行を選択して「この範囲をタスクに割り当て」できる
  - 空白時間を埋めるときの手がかりにする

### 9.4 タスクトレイ

- **Phase 1 では作らない**（tkinter に機能がなく、外部パッケージが必要なため）
- 代わりに常時表示の折りたたみと右クリックメニューで操作する

## 11. 開発ステップ

1. **収集のみのスクリプト**
   - `python collector_test.py` でコンソール上にタイトルの変化を表示しつつ SQLite に記録
   - 無操作・スリープ推定もここで入れる
   - 数日動かして、PowerPoint・VS Code・リモートのタイトルの取れ方を確認する
2. **タスク・割り当ての基盤**
   - `task_service.py`：作成（`親/子` 入力）、切替、さかのぼり、重なりの切り詰め
   - 異常終了時の補正
   - 重なりの切り詰めは境界条件が多いので、ここだけは単体テスト（`unittest`）を書く
3. **常時表示＋切替小窓**（`main.pyw` で常駐化）
4. **簡易確認画面**
5. **自動起動の設定**（スタートアップにショートカット）
6. **自分で 1〜2 週間使う** → 12章の検証

## 12. Phase 1 で検証すること

| 項目 | 見るもの | 次の判断 |
|---|---|---|
| タイトルの情報量 | 手順書・メモ・接続先が判別できるか | 切り出しルールの調整 |
| 登録忘れ | 忘れた回数、さかのぼりで直せた割合 | 定期確認（Phase 2）の優先度 |
| リモート内の切替 | リモート内で作業が変わった頻度 | 定期確認の間隔 |
| 常時表示 | リモート全画面時に隠れないか、見慣れて無視していないか、クリックでフォーカスが移るのが気にならないか | 表示方法の調整 |
| 切替の手間 | ホットキーなしで不便か | グローバルホットキーの導入（13章） |
| 推定の精度 | スリープ・終了の補正が実態と合っているか | 閾値の調整 |
| 見返しの手間 | 一番面倒だった作業 | 見返し画面（Phase 3）の優先度 |

## 13. 後続フェーズの概要

### Phase 2：定期確認

- 30〜60分おきに常時表示の2行目で「まだこの作業中？ [はい] [変更]」
- 別ウィンドウのポップアップにせず、常時表示の中に出す。無視したら `ignored` として記録
- 「変更」時はタイトル履歴から切り替わったらしい時刻を候補表示
- 前倒しのきっかけ：その日最初の操作、離席からの復帰、新しい手順書の検知（Phase 4）
- 変化がないときは間隔を空け、「聞かれる＝何か変わったかも」と意識させる（形骸化対策）

### Phase 3：見返し画面

- tkinter の `Canvas` で描画
- 5／10／15分の時間枠ごとに「何を何分開いていたか」を上位3件＋その他で表示
- 枠の色は一番長かった種別で付ける
- 枠をクリック、または複数枠をドラッグしてタスクを割り当て（時刻で保存するので枠幅を変えても壊れない）
- 前後の枠と中身が大きく違う箇所に「切り替わったかも」マーク
- 定期確認の回答マーク、「次の未割当へ」、元に戻す
- 上部に稼働時間・未割当時間の要約

### Phase 4：手順書の検知と候補表示

- 新しい手順書を開いたら「手順書B.pptx [切替] [無視]」
- 範囲割り当て時にファイルとタスクの紐づけを自動学習
- 見返し画面で紐づけ済みの区間を候補として点線表示

### Phase 5：ツリー管理と集計

- `ttk.Treeview` でドラッグによる親の付け替え、名前変更、統合、アーカイブ
- 各ノードに今週・今月の合計時間
- 階層は 2〜3 段までを目安にする

### 必要になったら検討する改善（妥協部分の解消）

| 妥協した点 | 改善方法 |
|---|---|
| グローバルホットキーなし | 別スレッドで `RegisterHotKey` ＋メッセージループを回し、`queue` 経由で tkinter に通知 |
| ロック・スリープは推定 | 隠しウィンドウで `WTSRegisterSessionNotification` / 電源イベントを受け取る |
| 常時表示がフォーカスを奪う | ウィンドウハンドルに `WS_EX_NOACTIVATE` を ctypes で設定（tkinter との相性を要確認） |
| タスクトレイなし | 外部パッケージが使えるなら pystray を導入 |

## 14. 注意点・リスク
- **pywin32 の導入可否**：pip で入れられない場合は ctypes に置き換える（`winapi.py` のみ修正）
- **リモートデスクトップ全画面**：最前面ウィンドウが隠れる可能性あり。隠れる場合はウィンドウ表示で使う
- **リモート内の作業は区別できない**：タイトルが変わらないため。Phase 2 の定期確認で補う
- **ロック・スリープの推定誤差**：数十秒〜数分のずれは許容する
- **形骸化**：常時表示や確認に慣れて無視するようになる。表示は普段は控えめにし、注意が必要なときだけ変化させる
- **見返しの負担**：重いと使わなくなる。必須にせず、記録だけでも粗いログになるようにする
